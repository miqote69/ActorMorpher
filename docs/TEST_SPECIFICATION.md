# Test Specification

## Model scale cases

| ID | Requirement / failure | Preconditions and input | Actions | Expected result and evidence | Cleanup |
| --- | --- | --- | --- | --- | --- |
| AM-SCALE-001 | Source NPC scale was omitted | Model Search source row has a finite positive Scale | Build its `AppearanceData` | Model scale equals the source row value; rows differing only by scale are not collapsed | None |
| AM-SCALE-002 | Original scale must survive the first apply | Fake actor starts with scale A; desired has scale B | Apply desired and process one redraw | Override Base keeps A and visible desired keeps B | Dispose service |
| AM-SCALE-003 | Human-to-Human reset must not lose either scale | Base A, first Human B, second Human C | Apply first, then second | Clean transition writes A before final C; final state is C | Restore/dispose |
| AM-SCALE-004 | Restore returned the wrong prior state | Base A and desired B | Apply, then Restore | Both restore redraws use A and override state is removed | Dispose service |
| AM-SCALE-005 | Failed apply must restore scale | Base A; desired B is configured to fail verification | Process through rollback | Current state returns to A and store returns to its prior state | Dispose service |
| AM-SCALE-006 | Territory reapply must retain desired scale but capture a fresh base | Retained desired B; territory changes; new actor base is C | Start reapply, then restore | Reapply uses B; restore uses C | Clear persistence |
| AM-SCALE-007 | Invalid scale must not become a native write | Source scale is zero, negative, NaN, or infinity | Build appearance / apply | Scale is treated as unavailable; no invalid native scale write occurs | None |
| AM-SCALE-008 | Redraw success previously ignored scale | Native actor and finite desired scale B | Recreate and finalize draw object | `IsApplied` succeeds only when recreated `CharacterBase.ModelScale` equals B within tolerance | Restore actor |
| AM-SCALE-009 | Ryne had player-sized height | Debug plugin loaded; local player normal; select `BNpcBase#10072` | Apply Ryne once | Final log has `ModelCharaId=2720`, `SourceRowId=10072`, `CharacterBaseModelScale=0.84`; no crash or T-pose | Press Restore |
| AM-SCALE-010 | Restore must return the exact original player scale | AM-SCALE-009 completed and pre-apply scale recorded | Restore original state | Final model and equipment match the original player and `CharacterBaseModelScale` equals the pre-apply value | Leave actor restored |
| AM-SCALE-011 | A cutscene copy kept Ryne equipment but rebuilt a Hyur female face | Ryne Desired data is retained; a cutscene target is copied from source ObjectIndex 0 through `CharacterSetupContainer.CopyFromCharacter` | Enter the cutscene and let the copied target create its draw object | The target is linked to parent 0 before its draw creation and receives active ModelChara ID 2720, Ryne Customize and scale, plus the retained current local-player equipment exactly once; Actor Morpher queues no redraw or retry | Press Restore |
| AM-SCALE-012 | Other actors must remain untouched | Retained local-player Desired data exists; a non-local Character calls `EnableDraw` | Let that actor create its draw object | Original model, Customize, Equipment, and scale pass through unchanged | None |
| AM-SCALE-013 | Restore and logout must stop creation injection | Retained local-player Desired data exists | Restore or log out, then let the local player call `EnableDraw` | Original local-player creation data is used; no retained appearance is injected | Leave actor restored or logged out |
| AM-SCALE-014 | Static `GameObject.EnableDraw` invocation left the player hidden | Debug plugin loaded; local player visible; actual local actor vtable available | Install the local hook from that actor's current vtable slot, apply Ryne through normal virtual dispatch | Apply reaches `AfterRedraw`, the player remains visible, and no static base `EnableDraw` implementation is invoked directly | Press Restore |
| AM-SCALE-015 | A reused cutscene slot could inherit a stale local-player link | A cutscene slot was linked to parent 0 and then its Character virtual destructor runs | Reuse the same slot for an unmapped or non-local cutscene actor and create its draw object | The link is cleared before reuse; original creation arguments pass through unchanged | None |
| AM-SCALE-016 | Parent detection must not guess from names or periodically reapply | Ryne Desired data is retained; unrelated actor names may match the player or NPC | Remain in the field and enter/leave a cutscene | Only explicit `CopyFromCharacter` links can authorize cutscene injection; no framework polling, name comparison, queued redraw, retry, automatic rollback, or unverified indirect-copy hook is introduced | Press Restore |
| AM-SCALE-017 | A player-configured outfit was replaced by Ryne's Model Search outfit on cutscene entry | Apply Ryne, then successfully apply a Bulk Outfit to the local player before `CopyFromCharacter` copies ObjectIndex 0 | Enter the cutscene and compare all ten equipment values with that successful Bulk Outfit result | The cutscene copy keeps the active Ryne ModelChara ID, Customize, and model scale while using the exact current retained equipment; it does not read another actor or an older Model Search outfit | Press Restore |
| AM-SCALE-018 | Requiring the source draw object prevented cutscene linking and restored the Hyur face | Ryne is active; the game has removed the source draw object before `CopyFromCharacter` | Enter the cutscene | The target is still linked from explicit source ObjectIndex 0 and receives the retained current Ryne composition once, with no source draw-object dependency | Press Restore |
| AM-SCALE-019 | Returning from the cutscene replaced the Bulk Outfit with Ryne's Model Search equipment | AM-SCALE-017 is active in the cutscene | Leave the cutscene and let the field local player recreate its draw object | Ryne model/Customize/scale and the same latest successful Bulk Outfit equipment remain visible; no stale Model Search equipment is restored | Press Restore |

Automated cases use existing fake resolver, memory, redraw backend, and client context only for managed state-machine behavior. AM-SCALE-008 through AM-SCALE-019 require the actual plugin path and actual native actor; fixture or mock results cannot replace them.

## Command registration cases

| ID | Requirement / failure | Preconditions and input | Actions | Expected result and evidence | Cleanup |
| --- | --- | --- | --- | --- | --- |
| AM-CMD-001 | A duplicate instance removed commands it never registered | First instance owns a command; second instance observes it occupied | Initialize then dispose the second registration lease | Second instance never calls Add or Remove and the first handler remains registered | Dispose first lease |
| AM-CMD-002 | Commands stayed missing after the owning instance unloaded | Second instance initially observes an occupied command, then the first owner removes it | Run the remaining instance's next registration check | Remaining instance calls Add once, records ownership, and later removes only its own handler | Dispose remaining lease |
| AM-CMD-003 | Normal lifecycle must remain unchanged | Command is initially free | Register, repeat the registration check, then dispose | Add runs once, repeated checks do nothing, Remove runs once | None |
| AM-CMD-004 | Repository update plus Dev Plugin reload made both documented commands unavailable | Repository Actor Morpher and Dev ActorMorpher are loaded; one instance is then unloaded | Enter `/actormorpher`, close the window, then enter `/amorph` | Both commands are found and each opens Actor Morpher; Dalamud log has no repeated registration error after ownership transfers | Disable the duplicate instance |
