## Current appearance contract

`APPEARANCE_APPLICATION_SPEC.md` is the normative source. Model Search source B is supplied once without an Apply-time admission, normalization, or rendered-readback gate during one synchronous `DisableDraw -> EnableDraw` transaction, and temporary backing is restored in `finally`. The removable transaction substitutes B only at the normal game consumer inputs reached by that transaction and performs no post-Create repair call. Terminal Apply success requires a non-null requested Create; consumer arrival/completion is a passive diagnostic observation and cannot change that result, C publication, backing cleanup, or later Apply behavior. It does not run a post-Apply appearance readback or Verify gate. On success, the complete selected-NPC payload is reclassified as current C for the exact target Representation and published by the existing `ActorRegistry` / `ActorSnapshot` state; queued, rejected, and failed requests do not publish C.

The existing `ActorRegistry` / `ActorSnapshot` lane owns and publishes the one shared **Current User Appearance/Equipment snapshot** on every Framework update. A Human Model Search source supplies its own Facewear (`NpcEquip.Glasses[0]` row ID, or `0`), hat visibility (effective NPC head model nonzero), and exact `ENpcBase` / `BNpcBase` Scale in addition to the existing model, Customize, equipment, weapons, and Visor values. Apply success publishes that complete NPC-owned payload as C and later refreshes must not replace NPC-owned fields with restored target backing A. Actor list, Actor detail, and field/cutscene/GPose transition consume the same immutable `AppearanceData` for the selected Representation. Existing `LocalPlayerAppearancePersistence` may retain that same instance and key for a transition, but neither it nor the UI assembles another value authority.

No case authorizes B, backing A, past C, a partial assembly, inference, reverse mapping, or fallback as substitute data. Category-specific `N/A` is not a capture failure and cannot receive another category's past value. `POST_CREATE_HUMAN_10SLOT` was withdrawn by the User on 2026-09-02 after runtime failure and is not current behavior. Apart from the removable consumer-input transaction and its passive completion observation, no case authorizes a new hook/component, post-Create repair call, native-pointer cache, creation observer, or any unapproved skip, reject, retry, rollback, automatic reapply, clear, or capture-failure behavior. `ARM_AFTER_COMPLETE_C — User approved (2026-09-01)` remains the sole new safety measure: only a non-null C complete under the exact existing publisher predicate below and published by the normal publisher for the same source Representation may arm; null, partial, or unsupported data defers the transition, and an earlier different Representation may temporarily show the game's native appearance. No other new safety measure is introduced.
